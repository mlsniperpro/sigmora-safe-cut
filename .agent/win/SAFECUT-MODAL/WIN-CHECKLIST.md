Every requirement of `.agent/briefs/SAFECUT-MODAL.md`, the COMMON quality bar as it applies to this lane, and the
judging criteria it moves, each with its evidence. `- [x]` done, `- [P]` waits on an owner input (root

## 1. Scale to zero

- [x] `SafeCutApi`: `min_containers=0`, `max_containers=1`, `scaledown_window=300` (justified: longer than the 60 s per-minute rate window, short enough that a sleep's tail costs about half a cent). `tests/test_deploy.py::test_the_api_scales_to_zero_and_never_scales_out_to_two_copies`.
- [x] Sized to one container's real work: 1 core, 2 GiB (was 2 cores, 4 GiB). Measured: the replay pipeline peaks at 210 MiB RSS and averages ~2.2 cores while rendering; Modal bills max(request, use) and lets a container burst past its request, so the request is the idle cost.
- [x] A started job always finishes even if the tab closes: every queued action spawns the class's own `hold(job_id)` input (`Worker(keepalive=…)`, `Service.hold`), so Modal never scales the container down under it. Rejected alternatives recorded in `docs/DEPLOY-COSTS.md`.
- [x] Proof by killing the container mid-job: `tests/test_scale_to_zero.py::test_a_job_finishes_when_its_container_is_killed_mid_analysis_and_mid_audit` (SIGKILL of a real uvicorn API mid-analysis and mid-audit; the restarted process finishes the job, `validate_job_dir` passes, the receipt verifies, every stage logs exactly one `done`, the interrupted audit started twice and the finished `track` once: no finished stage is paid for twice).
- [x] No job stuck forever: `hold` resumes a job nothing is moving (`recover(only=…)`), the 15-minute cron spawns `hold` for any job still mid-action (wakes a container), and a job active past 45 minutes fails as `internal`. Tests: `test_hold_resumes_a_job_nothing_is_moving`, `test_a_stalled_job_fails_instead_of_holding_the_container_forever`, `test_recover_never_runs_a_job_twice`, `test_hold_gives_up_at_its_limit`.
- [x] A keepalive that fails never fails the request (`test_a_failing_keepalive_never_fails_the_request`); `Service.start` runs once whether Modal's `@modal.enter` or the ASGI lifespan calls it first (`test_start_runs_once_whoever_calls_it`).
- [x] Cold start measured and cut: `import safecut.api.app` 1.06 s → 0.74 s (scipy imported on first use in `safecut/decide/geometry.py`; three runs each).
- [x] Web app tolerates a cold start: 60 s first wait, retries only for idempotent calls, "Waking Safe Cut up" after 4 s in a polite status region (`web/src/lib/wake.ts`, `api.ts`, `WakingNotice.tsx`); unit tests in `wake.test.ts`, `api.test.ts`, `WakingNotice.test.tsx`; `tests/test_deploy.py::test_the_web_app_counts_the_api_awake_only_inside_its_scaledown_window` ties the web app's awake window to the API's `scaledown_window`.
- [x] Playwright with a delayed fake API: `pnpm e2e` holds the first requests, sees the waking line (axe: no serious or critical), then the labelled demo job loads and plays, and opens at once on reload after the wake.
- [x] Daily USD cap and spend ledger survive a sleep (SQLite on the Volume): `test_the_daily_cap_holds_across_a_restart`.
- [x] Per-IP limits across a sleep, decided: the per-hour paid-action limit moved to SQLite on the Volume (`StoredRateLimiter`; `test_the_paid_action_limit_survives_a_restart`, `test_a_restart_never_resets_the_paid_limit_through_the_api`); the per-minute limit stays in memory because a sleep needs a quiet spell longer than its window (`test_the_api_only_sleeps_after_a_quiet_spell_longer_than_the_per_minute_window`, `test_the_per_minute_limit_is_in_memory`). The ledger smoke on the Volume checks the limiter too.
- [x] `cleanup` at Modal's smallest request (0.125 core, 128 MiB, `scaledown_window=2`): `test_the_cron_runs_on_the_smallest_container_and_wakes_stranded_jobs`.
- [x] Idle and per-job cost table, labelled estimates, from `modal billing rates`: `docs/DEPLOY-COSTS.md`, `docs/SUBMISSION.md` ("Running cost"), `web/README.md`; generated by `python -m deploy.costs`; `test_the_cost_tables_match_the_code_and_the_containers` keeps all three and the container sizes in step.

## 2. EgoBlur Gen 2 on a GPU

- [x] `egoblur_detect` GPU function: the `audit` group image (pinned egoblur, torch, torchvision, vrs), `/models` from `safecut-models`, `/audit` from the handoff Volume `safecut-audit` (instead of `/data` from `safecut-jobs`; see the next line), `max_containers=4`, `min_containers=0`, `scaledown_window=30`, `gpu=["L4", "T4"]` (L4 first: several times the T4's FP32 throughput for 1.36× the price), bounded retries. `test_egoblur_runs_on_a_gpu_function_with_the_weights_and_the_handoff_volume`.
- [x] Reads the render from a Volume (the brief's commit-then-reload), not frames over the wire: a dedicated handoff Volume `safecut-audit`, since committing the jobs Volume from the API also reloads it, which Modal refuses while the ledger's SQLite files are open there (round-1 audit H1, verified in modal 1.6.2 `volume.py`); the answer carries the render's SHA-256, so a stale Volume view is caught and retried once. `test_the_audit_falls_back_to_yunet_and_says_so[stale]`, `test_answers_are_cached_per_render`.
- [x] Weights' SHA-256 verified before use (pinned in `safecut/audit/detectors.py`, also on the local path): `test_egoblur_gen2_weights_are_pinned_to_the_owners_upload`, `[altered_weights]`, `test_altered_egoblur_weights_fall_back_to_yunet_locally`.
- [x] The API container stays slim (no torch, no `audit` group): `test_egoblur_runs_on_a_gpu_function_with_the_weights_and_the_handoff_volume`; `SAFECUT_AUDIT_GPU=1` in the API image.
- [x] The auto-patch loop re-audits through the same GPU path: `test_a_leak_is_patched_and_rechecked_on_the_gpu` (the E4 injected leak, re-scanned on the GPU, the Volume committed before each call).
- [x] GPU seconds in the up-front estimate (`estimate_usd(…, settings)`), the cap check (ledger reservation per call, a cap that can't cover it falls back without calling), the ledger and `cost.jsonl` (`provider: "modal"`, estimated) and the receipt (`cost_usd_gpu`). - [x] `audit.json` (`egoblur.model`, `egoblur.device`), the receipt (`auditor`, `auditor_device`, HTML "on cuda:…") and `raw/audit/gpu.json` name the detector and device that actually ran; `validate_job_dir` cross-checks the device; earlier receipts still verify (new fields omitted while unset, like `responses_delete_pending`).

## Judging criteria this lane moves

- [x] Use of Meta AI tooling (25): every judge's render is audited by Meta's EgoBlur Gen 2 on a GPU, and the receipt says so with the GPU's name.
- [x] Technical depth and execution (20), "holds up in production": scale-to-zero with a proven no-stranded-job design, state that survives a sleep, a bounded and priced GPU path with every fallback tested.
- [x] Impact (30): the service costs about nothing while idle, so it can stay up for judges and after the event on a small budget.
- [x] Demo (25): the cold start is a designed, labelled state; the demo job still opens at once after a wake.
