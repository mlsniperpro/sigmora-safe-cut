### 1.1 Request **[GH-cookbook]**
- `POST /v1/responses` with `model: "sam-3.1"`, `stream: true`.
- `input` is one user message whose content is `[{"type":"input_text","text":"<noun phrase>"}, <media part>]`.
  - Image: `{"type":"input_image","image_url":"data:image/jpeg;base64,…"}`.
  - Video: upload first (`POST /v1/files`, `purpose=user_data`), then `{"type":"input_video","file_id":"file-…"}`.
- **One noun phrase per request.** The cookbook says "pass multiple concepts to run separate requests and combine their summaries in application code".
- **File IDs:** Meta's own examples use **both** `file-…` (the cookbook's SAM recipe, whose check rejects anything else) and `file_…` (ARCHITECTURE §3.2's example, from the docs). **Decided:** WP0's client and `contracts.py` accept both spellings (`file-` or `file_` followed by the server's ID) and treat the ID as opaque otherwise. Don't copy the cookbook's `startswith("file-")` check.
- The cookbook's verified run: `ping pong ball` on a 134-frame MP4 returned one stable object across all 134 frames; `duck` on an image returned 5 masks.

### 1.2 Request metadata **[GH-sam]**
| `metadata` key | Values | Effect |
|---|---|---|
| `include_confidence` | the **string** `"true"` | Adds an optional per-record confidence `c` (0–1) to box and mask tokens |
| `propagation_direction` | `both` (default), `forward`, `backward` | For **object prompts** (below): which frames to track over |
| `mask_encoding` | `"one_bit"` (DESIGN §2.2) | **Documented** ([sam/segmenting](https://dev.meta.ai/docs/sam/segmenting), read 2026-10-25): top-level `metadata.mask_encoding`, `"lossless"` (default, `~`) or `"one_bit"` (`!`, "several times smaller than lossless"); "box and point prompts always return one_bit masks, whatever mask_encoding is set to. Read the marker on each mask" |

> 🔴 **This contradicts DESIGN.md's "there are no scores".** The protocol defines a confidence `c` on request. Readers "must accept records without `c` in every response, including responses to requests that ask for it", and "a missing confidence does not mean zero". Deny-by-default still holds (scores can be absent), but WP0 should probe `include_confidence` because a per-frame score would let the leak guard extend tracks at low-confidence frames instead of guessing.

### 1.3 Object prompts (box and point prompts) **[GH-sam]**
> 🔴 **This contradicts DESIGN.md §2.2 ("text prompts only").** Instead of a noun phrase, `input_text` may carry *object prompts* in the output token vocabulary:
```text
<30f>1<|box;x1=10;y1=20;x2=39;y2=59;w=640;h=480|>-<|point;x=25;y=30;w=640;h=480|><120f>1<|point;x=20;y=40;w=640;h=480|>,2<|box;x1=5;y1=5;x2=29;y2=29;w=640;h=480|>
```
- `<Nf>` opens a block for source frame N. Segments are `id` + tokens; the same id on another frame re-prompts the same object.
- `box` = whole object (inclusive x2/y2). `point` = a positive click; `-` before `<|point…|>` = a negative click.
- Every token carries `w`/`h` = the displayed media size (after rotation). Coordinates are integer pixels inside the media.
- A request must not mix a noun phrase with object prompts. "A model may limit how many objects one request can prompt."
- The response reports each object under the id the request gave it.

**Why it matters:** the miss loop (`docs/prompts/miss-loop.md`) can send Muse Spark's *point* straight to SAM as an object prompt on the exact frame, instead of hoping a new noun phrase finds the same thing. It can also re-acquire a lost track from its last box. WP1 should support both paths.

### 1.4 Output: the special-token stream **[GH-sam]**
One `output_text` lane, **one line per frame**, newline-terminated:
```text
<7f>0<|box;x1=10;y1=20;x2=14;y2=24;w=100;h=80|><|mask;x=0;y=0;data=5,5,!!!!!(QO(0lu8?|>
<7f>0<|box;x1=10;y1=20;x2=14;y2=24;w=100;h=80;c=0.75|><|mask;x=0;y=0;c=0.75;data=5,5,…|>
```
Grammar (normative summary):
- `line := "<" N "f" [";" fields] ">" segment ("," segment)*`. A comma before each segment is optional, including before the first.
- `segment := objectId token+`, where the record must have **exactly one `box` and exactly one `mask`**, in any order. Other tokens are ignored (with a warning).
- `objectId` is a non-negative decimal, stable within one response. It is **not dense**, needn't start at 0, and must be kept as a string, never derived from position.
- `token := "<|" name [";" key=value]* "|>"`, with `name ~ [A-Za-z][A-Za-z0-9_.-]*`. Fields are read by name; unknown keys are ignored with a warning.
- `box` requires `x1,y1,x2,y2` (integers, may be negative in syntax) plus `w,h` (the source size). **x2/y2 are inclusive**; normalised boxes are half-open (`right = x2+1`).
- `mask` requires `x=0`, `y=0`, `data=H,W,payload`. **H×W is the box size** (in the parser's example, box `x1=211..x2=270`, `y1=228..y2=254` carries `data=27,60,…`). So the mask is cropped to the box at source resolution and is placed at the box origin. DESIGN's "masks are smaller than the frame, so upscale them" really means *place*, not scale. WP0 confirms on a real clip whether the server downsamples.
- Payload: base85 text (not base64) over the alphabet ``!#$%&'()*+-./0123456789:=?@ABCDEFGHIJKLMNOPQRSTUVWXYZ[]^_`abcdefghijklmnopqrstuvwxyz{``. The first char is the encoding marker (`~` lossless, the API default; `!` one_bit), then a 5-digit length prefix and an arithmetic-coded body. **Treat it as opaque**: never regex it or interpolate it into a shell, since it contains `$*()[]` and backticks.
- **Frames without objects emit no line** (indices skip). **Lines may arrive out of frame order** (e.g. forward to the end, then backward to 0). Never assume indices increase.
- Zero matches is a valid completed response with no records.
- Streaming quirk: the live API emits `response.content_part.done` but **not** `response.output_text.done`. The official adapter accepts either as the lane finaliser. **[GH-cookbook]**

### 1.5 Client libraries **[GH-sam] [PyPI]**
- **Python: `meta-sam-parser` 0.1.0 on PyPI** (import `meta_sam_parser`), Python ≥3.10, with no runtime dependencies. **Licence: SAM License** (not MIT/Apache). That's fine as a dependency, but don't vendor its source into this MIT repo.
  - `parse_responses_stream(events, video_segmentation_format())` takes OpenAI-SDK events or plain dicts. Use it under `async with` and call `final_result()`.
  - The direct parser is `video_segmentation_format().create_parser()` → `.push(chunk)` / `.finish(CompletedOutcome())`.
  - Converters: `decode_mask_to_raster`, `decode_mask_to_rle` (exact COCO compressed RLE), `decode_mask_to_svg_path`. There's also an object-prompt text builder.
  - Results (`final_result()` of a parsed stream, or `.result` of the direct parser's `ParserFinish`): `.records` (box/mask records with `object_id`, `frame.frame_index`, `left/top/right/bottom`, `mask.encoding/width/height`), `.outcome.status`, `.diagnostics` (severity `error` = data dropped).
- TypeScript: `@meta-sam/parser` 0.1.0 (npm). Also `@meta-sam/react`, `/video` and `/graphics` in the same monorepo.
- **Consequence for WP1:** no hand-written stream parser is needed (WP1 confirms the Python names above against the installed 0.1.0 package on day 1; the live client-libraries page doesn't list them). Depend on `meta-sam-parser` and use `decode_mask_to_rle` for `tracks.json` masks. **Stored form (decided, §12):** `masks[f]` is a **frame-sized** COCO RLE (`size` = the prepared clip's `[H, W]`): the box-sized mask is placed at its box origin (rescaled first only if the proxy was downscaled) and re-encoded, so every reader uses one shape. Masks exist only on anchor frames (`from_proxy(j)`). On a frame between two anchors, the renderer's mask is the **union** of the two neighbouring anchors' masks, each shifted by its box's move to the interpolated box, then dilated as usual (WP3/WP4). A frame with only one neighbouring anchor uses that one. That keeps mask-shaped styles from flickering to boxes between anchors, and the union fails toward hiding more.

### 3.2 Structured output
- On Responses use `text: {"format": {"type":"json_schema","name":…,"schema":…,"strict":true}}`. `response_format` is **accepted and ignored** on Responses ([protocols/responses](https://dev.meta.ai/docs/protocols/responses) (read 2026-10-25): "they do not configure structured output on Responses"), so it would silently give unconstrained output: never send it. Limits ([structured-output](https://dev.meta.ai/docs/structured-output)): depth 10, 5,000 properties, 1,000 enum values, ≤ 200,000 nodes after inlining `$ref`s (all 400); `name` ≤ 64 chars `[a-zA-Z0-9_-]`; no `allOf`/`oneOf`, `anyOf` only below the root.
- Strict schemas must set `additionalProperties:false` and list **every** property in `required` (or HTTP 400). Use `enum` for closed sets. **Recursive `$ref` → 400.** Optional fields must therefore be required and nullable (`"type":["string","null"]`). **[GH-cookbook]**, **[3P]** inspect_ai #5222
- Constrained decoding "guarantees the output conforms". Still validate with pydantic (refusals and truncation exist).

### 3.3 `store: false`
- Supported. Stateless multi-turn uses `include: ["reasoning.encrypted_content"]` and replays reasoning items. That `include` can't be combined with `previous_response_id`. **[3P]** inspect_ai #5222, OpenClaw docs.
- With `store:false` there's no `previous_response_id` chaining; every Safe Cut call is single-turn anyway.

### 3.5 Streaming
- SSE events, OpenAI Responses style. Muse Spark reasons before any visible output, so a non-streamed call sits idle. Stream long calls, or set generous timeouts. **[3P]** inspect_ai #5222
- On a break, retrying restarts the stream from the beginning. **[GH-cookbook]** `02_streaming`

### 3.6 Errors **[GH-cookbook]** `09_error_handling`
- Envelope: `{"error":{"message","type","param","code"}}`. Branch on HTTP status and `type`; **`code` is often `null`**.
- Retry (exponential backoff + jitter, capped): **429, 5xx except 504, timeouts/connection errors** (§10.2). Never retry 400/401/402/403/404.
- On **Responses** ([protocols/responses](https://dev.meta.ai/docs/protocols/responses) (read 2026-10-25)): `stop`, `verbosity`, `logit_bias`, `prediction`, `n > 1` and audio modalities are **not implemented and have no effect** where accepted (the 400s are on Chat Completions). Still 400 on Responses: `logprobs` via `include`, `truncation: "auto"`, `tool_choice` other than `auto`, `reasoning.effort: "none"`. Safe Cut sends none of them.
- Context overflow → plain 400 with a message. [3P]
- Refusals: no structural refusal signal is documented for Muse Spark ([3P]). The SAM adapter treats refusal events and parts as terminal typed failures **[GH-sam]**.
- Every successful **token-based** response carries rate-limit budget headers ([pricing-rate-limits](https://dev.meta.ai/docs/pricing-rate-limits) (read 2026-10-25)); transcription responses don't, and SAM's aren't documented. Limits are per team, not per key.

### 3.7 Rate limits and caching
- `muse-spark-1.3`: **3,000 RPM, 4,000,000 TPM**. **[SNIP]** [pricing-rate-limits](https://dev.meta.ai/docs/pricing-rate-limits)
- `muse-wonder-1.0`: 3,000 RPM, 4M TPM. [3P]
- Prompt caching is **automatic** (identical leading tokens). An optional `prompt_cache_key` raises the hit rate, and `prompt_cache_retention: "in_memory"|"24h"` is a hint. - **Design consequence:** put stable content (system prompt, schema, scene context, *the keyframe images*) first, and per-vote variation last. Then votes 2 and 3 of the role pass are mostly cached input (§9).

## 4. Muse Voice Transcribe (`muse-voice-transcribe-1.0`) **[GH-cookbook]** `06_muse_voice/01_voice_api_fundamentals`
Docs: [speech-to-text](https://dev.meta.ai/docs/speech-to-text) · [api-reference/voice](https://dev.meta.ai/docs/api-reference/voice)

### 4.1 One-shot request
`POST https://api.meta.ai/v1/asr/transcribe[?sessionId=…]`, header `Authorization: Bearer $MODEL_API_KEY`, **multipart** with two parts:
- `request`: a **JSON part** (`application/json`), not form fields:
  ```json
  {"mode": "DIARIZATION", "model": "muse-voice-transcribe-1.0", "audioEncoding": "WAV",
   "keywords": ["Amina"], "languageBias": ["English"]}
  ```
- `audio`: the file. **Mono 16-bit WAV at 24 kHz (engine-native) or 16 kHz.** Convert with `ffmpeg -i in.mp4 -ac 1 -ar 24000 -sample_fmt s16 out.wav`.
- `mode`: `PUSH_TO_TALK` (default) | `ENDPOINTING` | `DIARIZATION`. ⚠️ **"The server ignores an unrecognised mode rather than rejecting it"**, so a typo silently transcribes in the wrong mode. Validate it client-side. A mode a model doesn't serve *is* rejected.
- `keywords` (names, jargon) and `languageBias` are lists of strings. **v1 sends `keywords: []`** (no creator note), and `languageBias` from `SAFECUT_ASR_LANGUAGE_BIAS` (below; `[]` means the field isn't sent). They nudge the model and don't guarantee a spelling.

### 4.2 Response
```json
{"sessionId": "…", "transcript": "…", "audioDurationMs": 30000,
 "turns": [{"speaker": "A", "startMs": 1520, "endMs": 3100, "transcript": "How is the weather?"}]}
```
- `turns` is always present (empty in `PUSH_TO_TALK`); `speaker` is optional, present in `DIARIZATION` only, a **bare letter** (`"A"`), and a turn the model never attributed has none ([api-reference/voice](https://dev.meta.ai/docs/api-reference/voice/schemas) (read 2026-10-25)). Turns carry `turnId`. Requests that fail before producing a transcript, and 429s, are **not billed**; ASR 500 → retry **once** ([speech-to-text](https://dev.meta.ai/docs/speech-to-text)).
- `endMs` is used by the cookbook's caption recipe (`07_sam/03…/build-demo-data.py`).
- "Diarization covers non-overlapping speech." Overlapping talk is a known gap.
- **Mapping to `transcript.json` (decided):** speaker letters map to `S1`, `S2`, … in order of first appearance (`"A"` → `"S1"` if A speaks first). That keeps the ARCHITECTURE §3.3 contract and the spark-1.2 fallback on one label scheme: `speaker` matches `^[SU][1-9][0-9]*$`, where `U` labels come from the fallback (`speech-fallback.md`: an uncertain voice, never reused) and from Voice Transcribe turns with no `speaker`. A `U` turn's words count as speech evidence, but it's never treated as the same speaker as any other turn. `startMs/1000` → `start`, `endMs/1000` → `end`, and `transcript` → `text`. The WAV is extracted from `prepared.mp4`, so turn times are on the **prepared clock** (§5b).

### 4.3 Limits and errors
- One-shot: **≤10 min of audio or ≤32 MB**, whichever comes first. 413 = body too big; 400 = too long (after decode) or malformed.
- Errors: 401 bad key, 404 bad endpoint, 429 rate limited, 500 "the server exceeded its processing budget".
- **25 languages** (documented, [speech-to-text](https://dev.meta.ai/docs/speech-to-text), read 2026-10-25): Arabic, Bengali, Dutch, English, French, German, Hebrew, Hindi, Indonesian, Italian, Japanese, Kannada, Korean, Malay, Mandarin Chinese, Marathi, Polish, Portuguese, Spanish, Tagalog, Tamil, Telugu, Thai, Turkish, Vietnamese. **Swahili is not supported**, and `languageBias` takes capitalised names (`["English", "French"]`). The README states the limit: on Swahili or Sheng speech the transcript rarely links participants, so they're held for the creator (`no_speech_link`), the safe direction. Punctuation, endpointing and speaker attribution are done by the model. **Decided:** v1 has **no** creator note or language field (PR #2's `/try` has neither, and adding one is scope the UI doesn't carry), so `languageBias` comes from `SAFECUT_ASR_LANGUAGE_BIAS` (default `["English"]`), never a constant in code. The hint "steers recognition … it does not force" (speech-to-text page), and the default is unmeasured: WP2 transcribes the 3 hero clips with `["English"]` and with the field omitted (≈ $0.02) and sets the default to whichever has fewer word errors, recorded in its PR. Prompt slots for the note are filled with "none". A DIARIZATION turn with **no** `speaker` (the field is optional in the API reference) gets a fresh `U<n>` label, like the fallback's uncertain voices.
- Streaming (`wss://api.meta.ai/v1/asr/realtime`) needs real-time pacing (a >5 s backlog → close 1008) and a 60-min cap. Not needed for Safe Cut.

## 5. Image understanding (points and boxes)
Docs: [image-understanding](https://dev.meta.ai/docs/image-understanding) (**read 2026-10-25**: "convert back to pixels using the dimensions of the exact image you sent: `x = round(x_norm * width / 1000)`, `y = round(y_norm * height / 1000)`"; "coordinates are relative to the image the model actually received")
- **0–1000 normalised grid** for both points and boxes, relative to the **image as sent** (after any client-side resize). Box example `[424,115,610,273]` = `[x1,y1,x2,y2]` ‰. **[3P]** Simon Willison's write-up of the meta.ai Muse Spark launch, **[DESIGN]**
- Edge case: **values of 1001 have been seen** → clamp to `[0,1000]` before mapping. **[DESIGN]**
- **The single mapping rule** (every spec points here). Keyframes are sent at the **prepared clip's own resolution** (≤1280 px; never resized again). The prompt specs add a black frame-number bar of `bar_h` **sent pixels** above the frame, so the sent image is `W × (H + bar_h)`:
  1. clamp each grid value to `[0, 1000]`;
  2. to sent-image pixels, **Meta's documented rule**: `x_img = round_half_up(vx × W / 1000)`, `y_img = round_half_up(vy × (H + bar_h) / 1000)` (`round_half_up(z) = floor(z + 0.5)`, never Python's banker's `round`); for a **point**, clamp to `[0, W − 1] × [0, H + bar_h − 1]`;
  3. to frame pixels: `x = x_img`, `y = y_img − bar_h`;
  4. **point:** if `y < 0` (it's in the bar), drop it; otherwise it's valid, since it's in-bounds by construction.
     **box:** Safe Cut pixel boxes are **half-open** `[x1, y1, x2, y2)`, the same convention as the parser's normalised `left/top/right/bottom` (§1.4). First **normalise reversed corners** (swap so that x1 ≤ x2 and y1 ≤ y2). A box lying **entirely inside the bar** (`y2_img ≤ bar_h`, with `y2_img` the mapped bottom edge) is dropped (log `in_bar`) **only** if it's a red-team `text` finding whose text matches the label (`F` plus digits, spaces ignored). **Any other in-bar box** (a face, person or plate finding, or text that isn't the label) is a misplaced real finding: the red-team keeps it as a leak with a **whole-frame box** (fail closed, like a malformed box), Role-pass and miss-loop boxes in the bar are dropped, and the item keeps its point if that's valid (G9, M9). Then map both corners with step 2 (unclamped) and step 3: the mapped bottom-right corner is already the **exclusive** edge (`x2 = x2_img`, `y2 = y2_img − bar_h`), since the grid is continuous over `[0, W]`. Clamp to `[0, W] × [0, H]`. If the clamped box is under 2 px in either dimension (e.g. a hairline, or a sliver clipped at the frame edge), a **red-team** box becomes a 32×32 px box centred on `((x1+x2) div 2, (y1+y2) div 2)` and clamped to the frame (fail closed: it still gets patched); a **miss-loop** box is discarded and its point kept. When a half-open box goes into a SAM object prompt, it's sent as inclusive `x2 − 1`, `y2 − 1`; `meta_sam_parser.build_object_prompt(PromptBox(left, top, right, bottom))` does this conversion. Test vectors: §11.2.
  **Decided (2026-10-25, live docs):** Meta's image-understanding page gives `round(x_norm × width / 1000)`, so PRE-A uses it (the earlier `floor(v/1000 × (W − 1))` guess is replaced; the two differ by ≤ 1 px at 1280). WP0 probe g still checks it on a synthetic image with a known dot. WP2 implements this rule once and property-tests it: outputs are in-bounds, monotone in the input, and the round trip from frame pixels is within 1 px.
- Exact point JSON (`{"x","y"}` vs `[x,y]` vs `<point>` text) is only defined by **our** schema, because we ask for points via `text.format`. The grid convention is the model's trained prior, so the prompt must state it explicitly (see `docs/prompts/role-pass.md`).
- Note: SAM object prompts (§1.3) need **pixel** coordinates with `w`/`h`, so convert the 0–1000 points before sending.

## 5b. Time and frame axes, the definition every WP uses
PRE-A owns this definition, and PR #2 applies it (`docs/labeling/LABEL-FORMAT.md` §2 and §9.1, `docs/UI-SPEC.md` §3.6, at `f6815a5`). It also matches DESIGN §2.1's existing `PreparedClip.times` ("source-second timestamps per frame"). Every ffmpeg behaviour below was **verified with ffmpeg 6.1.1** on 2026-10-24 by matching per-frame checksums before and after the filter (vectors T1–T6, T9, T10). No contract field changes.

**Decided (2026-10-24, final):** the prepared clip has a **constant frame rate**, and `times` holds **source-clock seconds**.
- *Rejected:* a variable-frame-rate prepared clip that keeps source timestamps. It was tried twice in this branch's history, and two problems were found by running ffmpeg. A drop-only `select` rule drops real frames from jittery 30 fps phone clips (36% of a ±1.5 ms-jitter clip). And `-fps_mode passthrough` re-quantises timestamps to the stream's frame rate unless `-enc_time_base demux` is set.
- The constant-rate clip keeps the player, the SAM proxy and the render on one fixed slot rule. It tolerates timestamp jitter (slots round to the nearest tick), and the existing Sigmora prepare already works this way.

**Two clocks:**

| Clock | Origin | Unit | Used by |
|---|---|---|---|
| **Prepared clock** | prepared frame 0 = 0.0 s | `t_p = i / job.fps` | player, overlay, SAM proxy, render, **transcript turn times**, every UI time display |
| **Source clock** | the first decoded **video** frame (its PTS, after the container's edit list, is subtracted) | `job.times[i]`, seconds | mapping CVAT labels (source frames) onto prepared frames; the receipt's "source time" |

**`prepare` (WP1), exactly:**
1. `job.fps = min(30, round(source average fps))`, an integer from 1 to 30. No ffprobe (step 3): **source average fps** = framemd5 packet count ÷ ((max `pts` + last packet's `duration` − min `pts`) × `time_base`); audio presence (`audio_codec`), rotation and size come from `imageio_ffmpeg.read_frames(...)`'s first (meta) item (keys `fps`, `size`, `source_size`, `rotate`, `audio_codec`, `duration`, checked 2026-10-25 on the bundled ffmpeg 7.0.2-static); ffmpeg auto-rotates when transcoding, so `prepared.mp4`'s size is read back from it (WP1.md's "ffprobe" step, §12). The output is constant frame rate at `job.fps`, H.264, `+faststart`, ≤1280 px long edge (DESIGN §2.1).
2. **Normalise the start first:** video filter chain `setpts=PTS-STARTPTS, fps=<job.fps>, scale=…`. Without `setpts`, a video stream that starts after its audio (or with a non-zero first PTS) makes the `fps` filter slot frames by absolute time, and the mapping shifts (verified: a 0.1 s video delay moved proxy frame 0 from prepared frame 1 to 2; T9). **Audio stays in sync on the same origin:** if the audio starts earlier than the video by `d` seconds, `atrim=start=d, asetpts=PTS-STARTPTS`; if it starts later, `adelay=d×1000:all=1`. Then the prepared audio and video both start at 0.
3. **Frame selection is ffmpeg's `fps` filter** (default `round=near`). Give source frame `k` the slot `s_k = round_half_up(t_k × job.fps)`, where `t_k` is its source-clock time. **Output frame `n` shows the last source frame with `s_k ≤ n`.** Earlier frames in the same slot are dropped, and an empty slot repeats the previous frame. **`times[n] = t_k` of that frame.** WP1 computes `times` from the per-frame PTS list with this rule, read with the **bundled** binary (`imageio-ffmpeg` ships ffmpeg only, no ffprobe): `ffmpeg -i <clip> -map 0:v:0 -c copy -f framemd5 -` prints one line per packet (`stream, dts, pts, duration, size, hash`) in the **stream's own** time base (`#tb 0: 1/15360` header) with exact integer `pts`, in **decode** order, so WP1 **sorts by `pts`** (B-frames reorder them). *Rejected:* decoding without `-c copy`: `framemd5` then re-times frames to its own output rate (`#tb 0: 1/30`), which loses VFR source times. Checked on ffmpeg 6.1.1 with a 30-frame x264 clip with B-frames, 2026-10-25 (sorted pts 0, 512, 1024, …; 30 lines); and its test checks the rule against ffmpeg's own output on a synthetic VFR clip (the bundled imageio-ffmpeg binary, with its version recorded).
4. **Exact arithmetic:** compute `t_k` from the **integer** `pts` and the stream `time_base` as a rational (`Fraction(pts − pts_0) × time_base`), not from ffprobe's 6-decimal `pts_time` string. `times` is stored as the **full-precision double** `float(Fraction(...))`, never rounded (the same rule PR #2 LABEL-FORMAT §2 states). Then every consumer that recomputes `t_k` with the same function gets bit-identical values, which PR #2's `|t_k − times[i]| ≤ 1e-6` match relies on.
5. Consequences a builder must not "fix":
   - `times` is **non-decreasing, not strictly increasing** (a gap repeats a frame);
   - `times[0]` is the time of the last source frame in slot 0, which **may be > 0** (T6c: 0.04);
   - **`job.frames` is the number of frames ffmpeg actually wrote, read back with the bundled ffmpeg's `framemd5` output (line count)**, never computed from duration × fps (the last source frame can fall in a slot ffmpeg doesn't emit at end of stream);
   - a jittery 30 fps source keeps every frame, because each frame's slot rounds to its own tick.
6. Audio is muxed in sync on the prepared clock. The ASR WAV is extracted **from `prepared.mp4`**, so `transcript.json` turn times are prepared-clock seconds. Turn time → prepared frame: `clamp(floor(t × job.fps), 0, job.frames − 1)`.
7. No trim in Safe Cut v1 (creators trim before upload; PR #2 UI-SPEC §2). If trimming is ever added, `job.json` gains `source_offset_s` (a contract change in ARCHITECTURE §3.1 and `contracts.py`).

**Mappings (one module in WP1):**
- **player → prepared frame** (PR #2 UI-SPEC §3.6): `i = clamp(floor(mediaTime × job.fps + 0.25), 0, job.frames − 1)`.
- **prepared frame → display time:** `i / job.fps` (m:ss).
- **ground truth: prepared → label** (PR #2 LABEL-FORMAT §2 and §9.1): prepared frame `i` takes the label state of the source frame `k(i)` with `|t_k − times[i]| ≤ 1e-6` (exact by step 4). Repeated prepared frames repeat that state; labels on dropped source frames are never sampled.
- **SAM proxy** (`sam_proxy.mp4`, §9): encoded from `prepared.mp4` with the `fps` filter at **`sam_fps_eff = min(SAFECUT_SAM_FPS, job.fps)`** (`SAFECUT_SAM_FPS` defaults to 8, a request to WP0; never upsample). `sam_frames` is read back the same way (bundled ffmpeg, `framemd5`). The same slot rule applies, now on prepared times `i / job.fps`:
  - `from_proxy(j) = max{ i < job.frames : round_half_up(i × sam_fps_eff / job.fps) ≤ j }`: SAM detections on proxy frame `j` belong to prepared frame `from_proxy(j)`. Prepared frames in between are filled by WP1's densify, which interpolates box corners linearly between anchors;
  - `to_proxy(f) = argmin_j |from_proxy(j) − f|`, ties → the smaller `j`, for object prompts on prepared frame `f`. Precompute `from_proxy` as an array of length `sam_frames`.
- **Parameters defined in SAM's own frames must be scaled to prepared frames.** SAM 3/3.1 confirms a new object only after `hotstart_delay = 15` frames of **its** input video (`facebookresearch/sam3` @ `f1647e8`, `model_builder.py`: the video builder and the 3.1 multiplex builder both set `hotstart_delay=15`; the hosted API is assumed to behave the same, *(probe)*). On the proxy that's `15 / sam_fps_eff` seconds. So:
  - **the leak guard's back-fill** (DESIGN §2.6: "back-fill 15 frames before first detection") becomes `ceil(15 × job.fps / sam_fps_eff)` prepared frames, which is 57 at 30 → 8 fps. `plan.json` `temporal.backfill` stores that prepared-frame value (request to WP3);
  - **gap and merge thresholds** that count SAM frames (e.g. WP1's `gap_merge_frames = 2`) are measured in **proxy** frames, before densify (request to WP1). Measured on prepared frames, every pair of 8 fps anchors (3–4 prepared frames apart) would look like a gap;
  - **crowded frames:** the 16-object cap (§1.6) is only ever seen on proxy frames. A proxy frame `j` whose detections hit it marks the **whole prepared span around it** as crowded: prepared frames `from_proxy(j−1) + 1` … `from_proxy(j+1) − 1`, with `0` for `j = 0` and `job.frames − 1` for the last proxy frame. `tracks.json` `crowded_frames` lists those **prepared** indices (ARCHITECTURE §3: frames index the prepared clip), so `plan.json` `crowd_fills` covers the frames between anchors too (fail closed; request to WP1 and WP3; vector T11). Listing only `from_proxy(j)` would leave 3 of every 4 prepared frames unfilled at 30 → 8 fps;
  - `temporal.extend` (8) and `gap_hold_s` (2.0 s) are already defined on the prepared clip and stay as they are.
- **Property tests (WP1):** every output is in bounds and every map is monotone; `to_proxy(from_proxy(j)) == j` for every `j`; and `|from_proxy(to_proxy(f)) − f| ≤ ceil(job.fps / sam_fps_eff)`. That bound was brute-forced for `job.fps` ∈ {6, 10, 15, 24, 25, 30}, `sam_fps` ∈ {6, 8, 10} and every clip length from 5 to 1,800 frames; the bound is **never exceeded**, and with ffmpeg's real end-of-stream count (the last slot may not be emitted, T1: 900 frames → 240) the observed maximum at 30 → 8 fps is **3** (80 of the lengths 5–400; `sam_frames = round_half_up(N × 8 / 30)`, which ffmpeg 6.1.1 `-vf fps=8` matched for every length checked, 2026-10-25), so tests assert `≤ ceil(job.fps / sam_fps_eff)`. Tests use the read-back `sam_frames`. Vectors are in §11.3.

## 8. Surprises WP0 should know before writing code
1. **SAM can return confidences** (`metadata.include_confidence: "true"`) and **accepts box/point prompts**. Both contradict DESIGN. §1.2–1.3.

3. **SAM lines can arrive out of frame order**, and object IDs are sparse strings. §1.4.

6. File IDs appear as both `file-…` and `file_…`, so accept both. ASR modes are case-sensitive and unknown modes are silently ignored. Speaker labels are letters.

### 10.2 Retries (one policy, `safecut/meta/retry.py`)
- **Retry on:** HTTP 429, 500, 502, 503, connect or read timeouts, **not 504** (Meta: "do not simply retry — the same request will usually time out again"; every long Safe Cut call streams, and a streaming 504 means the first event was late, so it's a `MetaUnavailable` without retry), connection resets, and a stream that ends with no terminal event (SAM `IncompleteOutcome(reason="eof")`). **Never retry:** 400, 401, 402, 403, 413, 422, refusals (the red-team's one rephrased re-ask, `redteam.md`, is its stage's single re-ask, §10.6, not a transport retry), a server-declared `status: "incomplete"`, or a schema-invalid but complete response (that gets one *re-ask*, §10.6, not a transport retry). A 404 is retried only as `MetaFileGone` (re-upload, §10.4). [GH-cookbook] `09_error_handling`.
- **Attempts** (the only retry counts in the repo; prompt specs refer here): Responses at `none`…`high`, ASR and Files: **4** in total, except an **ASR 500: 2 in total** (Meta: retry once; [speech-to-text](https://dev.meta.ai/docs/speech-to-text)), then the speech fallback (vector R14). Responses at `xhigh`/`max`: **2** in total (each attempt can cost ≈ $0.23, C4). **SAM: 2** in total, because every attempt re-bills the frames. A schema re-ask is one extra call on top of these, and only after a complete response.
- **Backoff:** `min(30, 1.0 × 2^(attempt−1)) + uniform(0, 1)` seconds (attempt 1 → 1–2 s, 2 → 2–3 s, 3 → 4–5 s). If the response has a `Retry-After` header (seconds or HTTP-date), wait `max(that, backoff)`, capped at 120 s (a longer `Retry-After` ends the attempts as `MetaUnavailable`). Meta **sends it** on 429 and on 503 `service_overloaded`/`backend_unavailable` (`Retry-After: 60`) ([error-handling](https://dev.meta.ai/docs/error-handling) (read 2026-10-25)).
- **Throttle before a 429:** read `x-ratelimit-remaining-requests` and `x-ratelimit-remaining-tokens` on Responses calls (the only ones that carry them, §3.7). When either is below 5% of its `x-ratelimit-limit-*`, delay new requests by 1 s and log `throttled`.
- **Circuit breaker:** counts **calls** that failed after exhausting their attempts, not individual attempts. Five such failures within 60 s open the breaker for 60 s. Then it's half-open: one trial call is allowed; success closes it, failure re-opens it for 60 s. While it's open, calls fail fast with `MetaUnavailable`. A hide-critical stage that fails transiently sends the job to **`retry_later`** (rules below the typed-error table). `/healthz` reports degraded while the breaker is open.
- **Cost accounting (honest numbers, AGENTS rule 9):**
  - **Who the caller is and where the sums live (decided):** the WP0 client takes a `Caller` context on every job (`code_kind`, `code_id`, the per-code cap, the line it belongs to, the code's window), built by WP5 (service) or `eval/run.py` (WP7). Reservations and spend for the daily cap, per-code caps, the pilot pool and the test line are kept in **one single-writer ledger**: a Modal function `budget` with `max_containers=1` that serialises `reserve`/`settle`/`release` calls and persists to the Volume (committing after each write); `eval/run.py` runs locally with one job at a time, so its line uses a local SQLite file. Two containers can then never pass the same stale sum (WP5 implements `budget`; WP0 implements the client side and the `Caller` type). **It fails closed:** a `reserve` that errors or gets no answer within 10 s makes no Meta call and raises `MetaUnavailable` (handled as §10.3: the stage fails closed, a hide-critical stage → job `retry_later`). Every reservation carries `job_id`, `call_id` and an expiry of 2.5 h (the 2 h segment limit, §10.1, plus margin); `settle` and `release` are idempotent per `call_id`, and the hourly sweeper (WP5 cron) settles each expired open reservation as an **estimated** charge (`estimated: true`, the reserved amount), so a killed worker can neither free money that may have been spent nor hold a cap forever.
  - Before each attempt, **reserve** its pre-call estimate (§10.5) against the **job cap**, and against the cap of **who started the job**: a judge or public access code, a Sigmora service key or `/healthz` → `SAFECUT_DAILY_USD_CAP` (and, when a judge or public entry sets its own optional `cap_usd`, that too, reported as `code_cap`); a pilot code → its $6 per-code cap and the $20 pilot total (PR #2 PILOTS §5, UI-SPEC request 20); the recording code → its $12 total; the `owner` code (WP5's runs on the deployed service) → its own `cap_usd` (≤ $6, WP5's budget); test-split eval runs → the $43.20 test line; other owner, eval and WP runs → the job cap only (their WP budgets are tracked from `cost.jsonl`, not enforced by the client, §12). `/healthz` counts against the daily cap (§9.2).
  - On success, replace the reservation with the actual cost from `usage`, logged `estimated: false`.
  - On a failure where the request was **rejected before processing** (any non-200 HTTP status received **before the first stream event**, which covers 429, other 4xx and an immediate 5xx, or a connect error), release the reservation and log `usd: 0`. **Except a 504, or any 5xx that arrives more than 30 s after sending:** the server may have been processing, so it counts as accepted (next bullet). Assumption: Meta doesn't bill requests that error before producing output. WP0 checks this against the console's billing after the probes.
  - On a failure **after** the request was accepted (read timeout or stream drop **after** the first event, and also a read timeout **before** the first event once the request was sent, because the server may already be processing it), billing is unknown. Keep the reservation as a charge against the **caps**, and log it with `estimated: true`. The same applies to a 200 response whose `usage` is missing or zero.
  - Reported figures (receipt `cost_usd`, README cost per minute, eval cost) sum **only `estimated: false` lines**. The receipt shows the estimated total as a separate line, "possibly billed: $x". So the caps are conservative and the reported numbers are measured.

The exception carries **`cap`**, one of `job`, `test_line` (both → `job_cap`), `code` (→ `code_cap`), `pilot_pool` (→ `pilot_pool_cap`) and `daily` (→ `daily_cap`), and is logged to `cost.jsonl` as a budget line (§10.5), so `eval/run.py` can tell a test-line stop from a job-cap outcome. An audit pass sets `audit.blocked_reason: "over_budget"` and `audit_budget_cause` instead. For the audit, the frames count in `unresolved` (§12) |

"Fails closed" means: for a stage that could only *add* keep evidence (role pass, escalation, scene pass, speech), the job continues with everything hidden and those **items** `needs_you` (the job itself goes on to `review`; docs/prompts/README.md rule 3; a failed scene pass also holds every would-be auto-keep, `hold: "no_scene"`, §12). For a stage that's needed to *hide* (SAM base sweep, render), the job can't be published. It goes to **`retry_later`** when the cause is transient (`MetaUnavailable`, `MetaRateLimited`, or an eof `MetaIncomplete`); WP5 re-queues it once after 5 min; if the re-queued run fails transiently again, the job goes to `failed` with `failure.reason: "upstream"` (PR #2 UI-SPEC request 1). Otherwise it goes to **`failed`**: `MetaAuthError`, `MetaConfigError`, `MetaBadRequest`, `MetaRefusal`, `BudgetExceeded`, and a **non-eof** `MetaIncomplete` (a server-declared incomplete, or a parser `error` diagnostic, S5), which is deterministic, so re-running wouldn't help. Their `failure.reason` is PR #2's deterministic set (UI-SPEC §2.6, adopted; no [Try again]): `config` (`MetaAuthError`, `MetaConfigError`), `bad_request` (`MetaBadRequest`), `refusal` (`MetaRefusal`), `incomplete` (non-eof `MetaIncomplete`); `BudgetExceeded` uses its cap names above. A segment cancelled at the 2 h limit (§10.1) sets `internal` (PR #2's retryable value: a slow run may pass on retry).

**The audit is the exception, because a rendered output already exists.** Any audit pass that can't run or finish (transient failure after its attempts, `BudgetExceeded`, or a refusal after the red-team's one rephrased re-ask) adds **every frame it should have audited** to `unresolved`, with `audit.blocked_reason` set to `audit_failed` or `over_budget` (§12), and for `over_budget` also `audit_budget_cause` (from the exception's `cap`, PR #2 UI-SPEC request 11). The job goes to **`needs_you`**, never `failed` or `retry_later`, and the review page offers PR #2's **[Run the audit again]** whenever `blocked_reason` is `audit_failed` or `over_budget` (the precedence in §12 puts either above `unresolved_leaks`, so a run with failed frames always offers it) (`POST /v1/jobs/{id}/audit`, PR #2 UI-SPEC request 11: it re-runs the audit pass on the existing render, with WP4's auto-patch loop exactly as after a first audit, so only a segment it patches is rendered again, and then **the receipt stage runs** as after a first audit; the creator's decisions aren't rendered again), except when the cause is `job_cap`, which would fail the same way (PR #2 UI-SPEC §4, §5.3). Publishing stays off through the one gate, `unresolved == 0`.

### 10.4 Files: idempotency and cleanup
- No idempotency key is documented for any endpoint, so idempotency is done **client-side through the job directory**:
  - before uploading, compute `sha256(file)`; if `jobs/<id>/files.json` already maps that hash to a live `file_id`, reuse it;
  - write `{name, sha256, file_id, purpose, created_at, deleted_at: null}` to `files.json` (the §12 fields) **before** the first use;
  - at the **end of each processing segment** (§10.1: review-ready, or render + audit done), and on cancel or failure, `DELETE /v1/files/{id}` for every entry. A 404 with JSON `code: "file_not_found"` counts as deleted; an empty-body 404 is `MetaConfigError` (wrong path), leaves `deleted_at` null and the receipt `files_deleted: false`. Then set `deleted_at`. Segment (b) never needs `sam_proxy.mp4`: audit patches are static boxes (`redteam.md`), so no SAM call runs after review. So no Meta file waits through a creator's review, and none outlives its segment;
  - **an upload that times out** (the server may have accepted it, but the id never arrived): before retrying, list files (`GET /v1/files`, documented in §2; its paging is checked in WP0's probes) and delete any whose `filename` (uploads are sent with the job-unique multipart filename `<job_id>-sam_proxy.mp4` / `<job_id>-prepared.mp4`; `files.json` `name` stays `sam_proxy.mp4`/`prepared.mp4`), `bytes` and `created_at` match this job's upload (the list is team-wide); write each one found to `files.json` first. If listing isn't available, the 6 h `expires_after` is the only backstop, so the receipt sets `files_deleted: false` with "one upload's id is unknown; Meta expires it within 6 h". `files_deleted: true` is written only when no upload is unaccounted for;
  - an hourly sweeper (the WP5 cron) deletes anything in any `files.json` older than **6 h** that has no `deleted_at`. Upload with **`expires_after` 21,600 s (6 h)** as the backstop. That's well above the 2 h segment limit (§10.1), so a running segment never loses its file. If one does anyway, `MetaFileGone` re-uploads it.
- A retried Responses call is a new response. Stage outputs are checkpointed in the job directory, so a re-run stage **reuses its saved response** only when the response was **successful** (a stage output with `status != "ok"`, an `audit_failed` or `over_budget` audit, or a budget stop is **never** reused: "Run the audit again" and a re-queue always call again) and its **checkpoint key** matches: the stage name plus the sha256 of its inputs (files, frame list, prompt version, model and effort). Audit checkpoints key on the render's sha256 too, so a re-render is never "audited" with an older render's results (a checkpoint, never `SAFECUT_REPLAY=1`: reuse inside a live job isn't demo mode, and the job's `mode` stays `live`) instead of calling again.

### 10.5 Pre-call cost estimate and `cost.jsonl`
Prices live in `safecut/config.py` as a dated table (the §6 values, `price_table_date = "2026-10-24"`, re-read on Oct 26).

| Call | Pre-call estimate (worst case, checked against the remaining caps) | `units` logged after the call | `usd` |
|---|---|---|---|
| Responses | `POST /v1/responses/input_tokens` count [GH-cookbook] × `P_in` + `max_output_tokens` × `P_out`. The count call is free *(probe)*, retried per §10.2 (4 attempts), and is replaced by a **fallback estimate** when it fails (any error, including a 404; count-call errors never raise a typed error or stop a stage) or returns less than it: 1,500 tokens per image (A3), ≈ 1,100 per sampled frame, i.e. **2,200 per second** of `input_video` at 2 fps (A4: 65k for 30 s), and 1.3 × the UTF-8 byte count of text / 4. The larger of the two is reserved, so an under-count can't overrun a cap | `{"input": in, "cached": c, "output": out, "reasoning": r}` from `usage` (`input_tokens`, `input_tokens_details.cached_tokens`, `output_tokens`, `output_tokens_details.reasoning_tokens`) | `(in − c) × P_in + c × P_cached + out × P_out` (reasoning is already inside `out`) |
| SAM video | `max(50, sam_frames) × $0.0002` | `{"frames": usage.video_frames_processed}` (documented, §1.7) | `frames × 0.20 / 1000` |
| ASR | `ceil(duration_s) × $0.00005` | `{"audio_s": floor(audioDurationMs / 1000)}` | `audio_s × 0.18 / 3600` (billing rounds down to whole seconds, [SNIP]) |
| Files | 0 | `{"bytes": n}` | 0 (no file price documented) |

- `max_output_tokens`: `medium` and lower 16,000 (also `omit`, the speech fallback's default, which needs ≥ 4,000); `high` and `xhigh` (used only if `config.py` sets them, e.g. the `xhigh` fallback in `escalation.md`) 32,000 on Spark and 24,000 on Wonder; Spark `max` 48,000 (worst-case escalation `17k × $1.25/M + 48k × $4.25/M` ≈ $0.23, C4); **Wonder `max` 24,000** (≈ $0.55; at 48k it would be $1.03, a third of the $3.00 job cap per call, and windows multiply it, §9.2). A response cut off by this limit is `MetaIncomplete`.
- `cost.jsonl` line: `{"ts", "job_id", "stage", "model", "attempt", "units", "usd", "estimated": bool, "request_id", "cap", "code_kind", "code_id"}`. `code_kind` is who started the job (`pilot`, `recording`, `judge`, `public`, `service`, `owner`, `eval`, or `system` for `/healthz` and the startup probe, PR #2 UI-SPEC request 20) and `code_id` the code's id (`null` only for `system` lines and for local owner, eval and WP runs that use no code, which log `code_kind` `owner` or `eval`; an `owner`-kind access code logs its id, so its cap sums by it). `system` lines have `job_id: null` and are written only by the single-writer `budget` function (§10.2) to the service-level `cost.jsonl` on the Volume (one writer per file, `research/modal.md`), which the daily-cap sum includes; the caps sum spend by them (§10.2). `request_id` is the response's `id` (or `x-request-id` if present), `null` when no call was made. **Budget line:** a `BudgetExceeded` stop writes one line with the stopped stage's name in a `stage: "budget:<stage>"` form, the model it would have called, `attempt: 0`, `units: {}`, `usd: 0`, `estimated: false`, `request_id: null` and `cap` set (§10.3); every other line has `cap: null`. This extends ARCHITECTURE §3.10 (one line per API call) with `job_id`, `attempt`, `estimated`, `cap`, `code_kind` and `code_id`, and with budget lines for stops that made no call; WP0 adds them to the contract.

### 10.6 Request and response shapes
**SAM video** (one request per concept or per object-prompt batch):
```json
{"model": "sam-3.1", "stream": true, "store": false,
 "metadata": {"include_confidence": "true", "mask_encoding": "one_bit"},
 "input": [{"type": "message", "role": "user", "content": [
   {"type": "input_text", "text": "face"},
   {"type": "input_video", "file_id": "file-abc123"}]}]}
```
- `store: false` follows AGENTS rule 6. Whether `sam-3.1` accepts it is unverified *(probe)*. If it's rejected (probe b), WP0 sets `SAFECUT_SAM_SEND_STORE=false` (default `true`; §12 env table), the client stops sending the field to SAM, and `sam-3.1` goes in the receipt's `data_handling.no_store_param` instead of `store_by_model`, so the receipt stays truthful. Never claim `store:false` for a call that didn't send it.
- **Send `metadata.mask_encoding: "one_bit"`** (documented, §1.2): several times smaller on the wire, and box/point prompts return `one_bit` anyway. The parser decodes both; read each mask's marker rather than assuming.
- Object prompts replace the noun phrase text with `build_object_prompt(...)` output, plus `metadata.propagation_direction: "both"`.
- Parse the stream with `parse_responses_stream(events, video_segmentation_format())`. The result's `.records` give box and mask records (from the direct parser, use `finish(...).result.records`); `.outcome.status` is `completed` or `incomplete`; `.diagnostics` with severity `error` means data was dropped, so treat the request as `MetaIncomplete` (fail closed) and log the lines.

**Muse Spark / Wonder** (role pass shown; the other passes differ only in content, schema name and effort):
```json
{"model": "muse-spark-1.3", "stream": true, "store": false,
 "reasoning": {"effort": "medium"}, "max_output_tokens": 16000,
 "input": [
   {"role": "system", "content": [{"type": "input_text", "text": "<system prompt>"}]},
   {"role": "user", "content": [
     {"type": "input_text", "text": "<role definitions + scene + transcript>"},
     {"type": "input_image", "image_url": "data:image/jpeg;base64,<F90>"},
     {"type": "input_text", "text": "<vote phrasing k + labels per frame>"}]}],
 "text": {"format": {"type": "json_schema", "name": "role_pass", "strict": true, "schema": {"…": "…"}}}}
```
- Images go **only** in the user message: images on other roles are **silently ignored**, not rejected ("The model does not process images attached to other roles", [image-understanding](https://dev.meta.ai/docs/image-understanding), read 2026-10-26), so the client **asserts** before sending that no image part sits outside a user message. They're JPEG at quality 90, sent at the prepared resolution plus a `bar_h = 40 px` frame-number bar (§5), ≤50 images per request.
- Don't send `temperature`, `top_p`, `stop`, `n`, `logprobs`, `logit_bias`, `response_format` or `truncation`: `temperature`/`top_p` are accepted (range 0–2 and (0, 1]) but Muse Spark "performs best" at the defaults; the others are no-ops or 400s on Responses (§3.6).
- The output is in `response.completed` → `response.output[]`: take the `type: "message"` item's `content[]` part with `type: "output_text"`. A `type: "refusal"` part → `MetaRefusal`. Parse the text as JSON, then validate with the pydantic model. If invalid, **re-ask once** with the same request, then fail closed.

**Files upload / delete:** **two uploads per job**: `sam_proxy.mp4` (≤10 fps, §5b; used by every SAM request) and `prepared.mp4` (the scene pass, and the speech fallback's soundtrack). Each is a multipart `POST /v1/files` with `purpose=user_data`, `file=@<job_id>-<name>` (job-unique multipart filename for the §10.4 cleanup match; `files.json` `name` stays `<name>`), `expires_after[anchor]=created_at`, `expires_after[seconds]=21600` → `{"id": "file-…" | "file_…", …}`. `DELETE /v1/files/{id}` → 200 `{"id", "deleted": true}`, or 404 with `code: "file_not_found"` (treated as deleted; an empty-body 404 is not, §10.4). The response bodies are OpenAI-compatible and unverified *(probe)*. Sending `prepared.mp4` to SAM by mistake multiplies the SAM cost by `job.fps / sam_fps` and breaks the frame indexing, so WP1's request builder takes the proxy's `file_id` from `files.json` by name.

**ASR:** see §4.1. Use `mode: "DIARIZATION"` (a mode the model doesn't serve "is rejected before any audio is accepted", [voice API fundamentals](https://dev.meta.ai/docs/cookbook/voice-api-fundamentals) (read 2026-10-25)). The WAV is extracted from `prepared.mp4` (mono, 16-bit, 24 kHz).

### 10.7 Startup probe and `/healthz`
**At startup only** (once per deploy): for each configured `(model, effort)` pair, send a minimal request (text "ok", `max_output_tokens: 16`, `store: false`); for SAM, a 64×64 PNG with the text `"square"` (≈ $0.0025). Any HTTP 200 counts as healthy, even `status: "incomplete"`, because reasoning may use up the 16 tokens. A 400 or 404 → `MetaConfigError` → refuse to start; 401/403 → `MetaAuthError` → refuse to start; 402 → `MetaBillingError` → start degraded with `/healthz` red and `POST /start` answering `503 billing`. **Exception, the speech-fallback pair** (`SAFECUT_SPEECH_FALLBACK_MODEL` with its effort): its 400/404 never refuses the start; the fallback is marked disabled, `/healthz` shows it amber, and a job whose Voice Transcribe call fails then gets `transcript.status: "failed"` and `hold: "no_speech"` (§12). 429, 5xx and timeouts retry per §10.2; after the last attempt the service **starts degraded** (`/healthz` red); only the **failed** `(model, effort)` pairs are re-probed: before Nov 5 at most **once an hour** for a text pair (≤ $0.0002 each, ≤ $0.025 a day for five pairs) and at most **every 6 hours** for SAM (≤ $0.01 a day), and from Nov 5 every 30 minutes and hourly; SAM is never re-probed once it passed, because the cause is transient and each stage's own retries and `retry_later` still fail closed. **Once per deploy, not per container:** on Modal a scaled-to-zero app cold-starts often, so the probe writes a marker with the deploy id to the Volume and skips if it's present. Its cost (≈ $0.003: the SAM image plus about five text pairs) is logged as a `system` line and counts in the pre-window `/healthz` line, whose $0.80 is a budget line bounded by rate, not an enforced cap (WP5 builds no cap for it): ≤ $0.47 of `/healthz` probes plus ≤ $0.16 of worst-case re-probes in 7 days (7 × $0.022) leaves $0.17, over 50 deploys.

**`/healthz`** (ARCHITECTURE §5: at most once a minute; **before Nov 5 00:00 UTC at most once every 5 minutes**, §9.2, with the last result and its time held by the single-writer `budget` function (one writer, `research/modal.md`), so every container shares one rate) first calls Meta's **free, unauthenticated `GET https://api.meta.ai/v1/status`** ([api-reference/status](https://dev.meta.ai/docs/api-reference/status) (read 2026-10-25); it returns `is_alive`, `service_status` and per-model statuses; checked live), and reports degraded if Meta does. Then, at the cadence above, it sends **one** text request to `SAFECUT_ROLE_MODEL` (which proves our key and models work) at `reasoning.effort: "minimal"`, `max_output_tokens: 16`. At most ≈ 110 input tokens ("a short text-only request is ~110 input tokens", [image-understanding](https://dev.meta.ai/docs/image-understanding), read 2026-10-26) + 16 output = (110 × $1.25 + 16 × $4.25) / 1M = **$0.000206** per check, so at most **$0.296 a day** (1,440 checks) even if it's polled every minute, and at most $0.059 a day (288 checks) before the window. It never calls SAM. Probe costs are logged with stage `healthz` and count against `SAFECUT_DAILY_USD_CAP`, which leaves $2.70 of the planned $3/day for jobs.

**Contract details for WP0** (decided; answers to a WP0 builder walk-through of `contracts.py` and `config.py`, 2026-10-25). Where ARCHITECTURE §3 shows only an example, these are the types:
- `job.json` `fps`: **int** 1–30 (§5b; ARCHITECTURE's example `30.0` becomes `30`); `sam_fps_eff` and `audit.sample_step` are int.
- `scene.participants[].speaker`: `str | null`, pattern `^[SU][1-9][0-9]*$` when set (§4.2). `scene.json` `model` and `roles.json` `model`: `str | null`, `null` when `status != "ok"` (no model answered).
- Failure placeholders (`roles.json` `status != "ok"`, or a failed vote): each track `role: "unsure"`, `votes` padded with `"unsure"`, `frames: []`, `evidence: ""`, `matches_participant: null`; each object `sensitive: true`, `content: ""`. `evidence` and `frames` have no minimum length.
- Cross-file rules (`source_kind` vs `job.audio`, box bounds vs `job.width`/`height`, `masks[f].size`) are **pipeline checks** in WP2/WP3 (and WP0's `validate_job_dir` helper), not single-model pydantic validators; per-file rules (turns sorted, `end ≥ start`, the speaker pattern) are model validators.
- `roles.tracks[]` escalation fields: `suggested_role`: `"participant"|"bystander"|"child"|null`; `null` for an `unsure` ruling, a failed escalation and an escalation `child` ruling (rule 2 locks the track instead: `role: "child"`, `escalated: true`); `escalation_evidence`: `str | null`; `escalation_frames`: `[int] | null`, `null` when none (as the §12 row, `escalation.md` and E3/E7 have it).
- `audit.json` `spots[]` (PR #2 request 18): optional, default `[]`; `spot_id`: str (`"s1"`, …; the UI shows `U<n>`); `first`/`last`: int; `boxes`: `{frame: [x1, y1, x2, y2]}` (frame keys as strings, JSON); `covered_by`: `item_id` str or `null`.
- `audit.json` `redteam[]`: one entry per frame sent, `{frame: int, finding: "none"}` or `{frame, finding: "hit", kind, text: str | null, detail: str, box: [x1, y1, x2, y2], confidence: "low"|"medium"|"high", excluded_by: item_id | null}` (`detail` is the model's one-line description, `redteam.md`; `text` is private, §12 handling rule) (`excluded_by` set when the kept-clear rule excluded it, vector L1).
- `audit.json` `leaks[].kind`: `"face"|"person"|"text"|"plate"|"screen"|"misaligned_redaction"|"other"` (`redteam.md` kinds plus EgoBlur's face and plate); `detector`: `"egoblur"|"redteam"`.
- `audit.json` `egoblur` when the detector never ran: `{model: <configured id>, faces: null, plates: null}`, with the top-level `audit.frames_scanned: 0` (ARCHITECTURE §3.8 keeps `frames_scanned` at the top level, not inside `egoblur`; its frames are in `unresolved`, L10).
- `receipt.json`: `models` is an open map `{stage: model_id}` (`sam`, `scene`, `roles`, `escalate`, `redteam`, `asr` or `speech_fallback`, `auditor`), only for stages that ran; `data_handling.notes: [str]` carries the retention text, the unknown-upload note and the prompt-cache note (§3.7); `data_handling.store` is **stored**, computed as `any(store_by_model.values())` when the receipt is written. The hash chain (`canonical_json`, `prev_hash` for a first receipt, re-approval) is WP4's to specify in `contracts.py` (ARCHITECTURE §3.9); PRE-A asks only that `canonical_json` be sorted keys, `(",", ":")` separators, UTF-8, and exclude `hash`.
- `files.json`: a JSON **array** of `{name, sha256, file_id: str | null, purpose: "user_data", created_at, deleted_at: str | null, orphan: bool = false}`; timestamps ISO 8601 UTC (`…Z`); a timed-out upload whose id never arrived is an entry with `file_id: null`, `orphan: true` (§10.4), and `files_deleted: true` requires no `orphan` entry left.
- `cost.jsonl`: one JSON object per line (WP0's helper reads lines, not one model); `ts` ISO 8601 UTC; `model`: `str | null` (`null` for Files calls); `units` of an `estimated: true` line are the reserved estimate's units; the startup probe logs `stage: "startup_probe"`.
- Boxes in `tracks.json`, `plan.json`, `audit.json` and `decisions.json`: **int** pixels, half-open; densify rounds **outward** (`floor` x1/y1, `ceil` x2/y2), so interpolation never shrinks a box.
- `plan.json` `frames[f][].grid`: `null` unless `style` is `pixelate`; `decisions.items[].style`: `null` for `keep` items; `plan.padding`: `{face: pct, default: pct, px: int}` as ARCHITECTURE shows (the "kind's spatial padding" is `face` for `person`/`child` items' face tracks, else `default`).
- `decisions.items[].kind` from the concept (PR #2 UI-SPEC §0): `face`/`person` → `person` (or `child`), `license plate` → `plate`, `screen`/`phone` → `screen`, `document`/`name badge` → `document`, anything else → `other`.

- Config: efforts, `max_output_tokens`, retry counts, timeouts and concurrency are **constants** in `config.py` (§10), not env vars, except the variables in the env table.
