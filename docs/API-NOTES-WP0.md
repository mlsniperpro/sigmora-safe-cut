## 13.2b Open-weight path (PRE-A §3.8, implemented)
`safecut/open_weight.py`, outside `safecut/meta/` because Baseten isn't the Meta Model API:
- **Request:** streamed Chat Completions to `https://inference.baseten.co/v1`. No `response_format` (Muse Spark Open doesn't support structured output), so the answer is validated client-side, and invalid JSON is a failed second opinion with no re-ask. `reasoning_effort` comes from `SAFECUT_OPEN_WEIGHT_EFFORT` (`omit` sends none). `max_tokens` is 16,000, ≤ 8 images per call (Baseten's "Max images per request 8", PRE-A §3.8), with a 300 s idle timeout and **no transport retry** (a failed call is a failed opinion; an accepted one keeps its estimate). `second_opinion` splits a frame set into ⌈N/8⌉ calls, up to 4 in parallel. The budget is all or nothing: the whole set's estimate must fit the $0.50 cap before the first call (else `BudgetExceeded` plus a `budget:redteam_open` line, and WP4 records `open_weight.status: "off"`). Failure is per batch (redteam.md): a batch that errors or answers invalid JSON contributes nothing, the others keep their findings, and `status` is `failed` with `frames` counting the finished batches. A finding whose box isn't 4 integers (or is missing) is kept with `box: null`, the whole frame. The code kind comes from the client's `Caller`, never from an argument.
- **Spend:** cost lines carry `provider: "baseten"` and reserve only against `SAFECUT_OPEN_WEIGHT_JOB_USD_CAP` (`cap: "baseten_job"`), never the Meta caps. With no `SAFECUT_OPEN_WEIGHT_PRICE` the call is refused. Baseten failures never trip the breaker that guards the Meta calls.
- **Probe h:** needs only `BASETEN_API_KEY`. It sends one request on 4 synthetic frames, one 8-image call and one 9-image call (`image_limit_holds`: `true` when 8 are answered and 9 refused with a 4xx), then 3 tries of the "AMINA K." grid check (passes at IoU ≥ 0.3 in 2 of 3), then one `omit` call to compare latency and reasoning tokens. Its reservations use Baseten's published price ($1.25 / $4.25 per M) until `SAFECUT_OPEN_WEIGHT_PRICE` is set, and the summary records which price was used. Calls run one at a time, each reserving its worst case ($0.076 for 4 frames, $0.084 for 8, $0.086 for 9, $0.071 for 1) and settling at its measured cost. Only if every earlier call failed after acceptance and kept its estimate ($0.528 in all) would the last (`omit`) call be stopped by the $0.50 cap, recorded as a `budget:` line. An 8-frame second-opinion batch reserves $0.084 (image data URLs count as images, 1,500 tokens each, never as text), so the $0.50 cap covers up to 46 frames per job (5 full batches plus one of 6: $0.498 reserved; 47 frames reserve $0.500 and are skipped). **Consequence (recorded decision):** a typical 30 s, 8-track hero clip has 64 pass-1 frames (8 batches, $0.67 reserved), so at the PRE-A defaults its second opinion is skipped as over the cap (`open_weight.status: "off"`), exactly as §3.8 prescribes rather than running partially. 80 % of each reservation is the 16,000 `max_tokens` worst case. Probe h measures real output and reasoning tokens, and §3.8 lets it lower `max_tokens`: at ~6,000 a batch reserves ≈ $0.04, and 64 frames fit. Until then the second opinion runs on clips of ≤ 46 sampled frames.
- **Gating:** `open_weight.enabled_for` requires `SAFECUT_OPEN_WEIGHT_AUDIT=on`, `job.consented`, and a code kind in `SAFECUT_OPEN_WEIGHT_CODE_KINDS` (only `owner`/`recording` are accepted).

## 13.4 Client facts other WPs build on

- **Retries:** 4 attempts (Responses up to `high`, ASR, Files); 2 (Responses `xhigh`/`max`, SAM, ASR 500). Backoff 1, 2, 4… s capped at 30 s, plus jitter; `Retry-After` is honoured up to 120 s and a longer one stops the call. 504 is never retried.
- **Breaker:** 5 calls failed after all their attempts within 60 s open it for 60 s, whether or not other calls succeed in between (a partial outage still opens it); then one trial call; only a success while half-open (the trial's) closes it, and a late success while it's still open doesn't. A call counts when it fails after all its attempts with a retryable error (5xx, timeouts, an exhausted 429); auth, billing and other 4xx errors don't count.
- **Streams:** SSE is split only on `\r\n`, `\r` and `\n` (WHATWG), never on U+2028/U+2029/U+0085, which JSON strings may carry raw.
- **Cost lines:** rejected before processing (a 4xx, 429 or immediate 5xx, a connect error, a cancellation before the request is handed to httpx) → `usd 0`; possibly processed (a 504 or a 5xx after 30 s, a read timeout, a stream cut after it started, a cancellation once the request is handed to httpx, even while it is still connecting, since nothing proves no byte left; a completed response without usage) → the reserved estimate with `estimated: true`; completed with usage → the measured cost, unless it is over 10× the reserved worst case, which is a malformed body and keeps the estimate. `contracts.measured_usd` sums them apart (AGENTS rule 9). This is deliberately stricter than PRE-A R14, which releases a failed Voice Transcribe call at `usd 0`: a 504 or slow 5xx from ASR keeps its (small) estimate too, because nothing in the response proves it wasn't processed. Only 429, 500, 502 and 503 are retried (§10.2); other 5xx fail at once.
- **Budget stop:** a call whose worst-case estimate doesn't fit a cap is never sent; a `budget:<stage>` line names the cap (`job`, `daily`, `code`, `pilot_pool`, `test_line`, or `baseten_job` for open-weight calls).
- **Files:** idempotent by SHA-256 through `files.json`; the multipart filename is `<job_id>-<name>`; `expires_after` is 21,600 s (a recorded deviation from WP0.md's 3,600 s, following PRE-A §10.4: 3,600 s is shorter than the 2 h segment limit, so a file could expire mid-job); a timed-out upload lists `/v1/files` to find and delete its orphan, or records `orphan: true` (so `files_deleted` can't be claimed). R10 is the helper `FileStore.call_with_reupload` (one re-upload, one repeat, then `MetaBadRequest`); WP0's only file-referencing calls are the one-shot D1 probes (b, c, e and f, which re-run by hand), so WP1 (SAM) and WP2 (scene, speech fallback) must wrap theirs in it (PR #3 requests). Cleanup fails closed: a listing without a `data` list or with `has_more: true` keeps the orphan open, and a DELETE counts only with `deleted: true`.
- **Streaming:** Responses and SAM always stream. A stream with no terminal event is `MetaIncomplete(eof=True)` and retried; a server `incomplete` or a refusal is billed at its usage and not retried.
