# Owner inputs (the whole entry)

Every lane's list merged into one, with the exact steps for each input. None of these blocks the code: the entry
runs end to end on the synthetic demo job (`fixtures/jobs/demo/`, labelled synthetic everywhere) until they arrive.
Tick an item only once it is done; done items are then removed from this list (`scripts/entry-check.sh` E12).

## Keys and accounts

- [ ] **`MODEL_API_KEY`** (the Meta Model API key with the hackathon credits): add it as a secret in this repo's cloud environment, with `api.meta.ai` allowed by its network policy, and in the Modal secret below. Then a session runs `bash scripts/go-live.sh fixtures/clips/SC-A-91-synthetic-20261030.mp4 --id live-smoke` (a smoke run: records a full job's raw responses under its USD cap; don't commit `fixtures/jobs/live-smoke/`, since the clip is drawn shapes), `uv run pytest -m live` (every Meta call's live test) and the WP0 probes (`uv run python -m scripts.probes.probes a b c d e f g`, ≤ $6).
- [ ] **Modal tokens** for the deploy (do **Make the repo public** first: while the repo is private CI gets no runner, and the deploy runs only after CI passes): create a token at modal.com (Settings → API tokens), then add `MODAL_TOKEN_ID` and `MODAL_TOKEN_SECRET` as GitHub repository secrets (Settings → Secrets and variables → Actions). Also create the Modal secret `safecut-secrets` (Modal dashboard → Secrets → Custom) holding `MODEL_API_KEY`, `SAFECUT_ACCESS_CODES`, `SAFECUT_SERVICE_KEYS` (a JSON list, `[{"name": "sigmora", "key": "<32+ random characters>"}]`), `SAFECUT_URL_SECRET` (any 32+ random characters), `SAFECUT_PUBLIC_URL` (the API's URL, known before the first deploy: `https://<your-modal-workspace>--safecut-api.modal.run`; the API refuses to start without it) and `SAFECUT_CORS_ORIGINS` (`["https://safecut.sigmora.org"]`). The deployed API refuses to start on an access code shorter than 12 characters, a service key or `SAFECUT_URL_SECRET` shorter than 32, or a `SAFECUT_PUBLIC_URL` that isn't https. The next push to `main` deploys (`.github/workflows/deploy.yml`); `bash scripts/deploy-check.sh <api-url> <web-url>` then checks it. After the first deploy, set the repository variables `SAFECUT_API_URL` (the API URL Modal prints) and `SAFECUT_WEB_URL` (`https://safecut.sigmora.org`) under Settings → Secrets and variables → Actions → Variables: until both exist the deploy workflow ends red ("Deploy not checked"), because nothing has health-checked the deployment. Then, after the Vercel step below (the check also loads the web app), re-run the workflow from the Actions tab (Run workflow) so the check runs. On that first deploy also check that Volume writes reach the cron: create a job through the app, then `modal volume ls safecut-jobs jobs` must list its directory (the API container never calls `jobs.commit()` and relies on Modal committing Volume writes in the background; `modal run deploy/modal_app.py::cleanup` printing `[]` proves nothing on a fresh deploy).
- [ ] **Don't push to `main` from Nov 5 to Nov 10** (judging): every push to main redeploys, a redeploy can briefly overlap two API containers on the same Volume and ledger, and a restart re-queues in-flight jobs. Merge fixes after the window, or redeploy deliberately at a quiet hour.
- [ ] **Decide the judges' daily budget** (`SAFECUT_DAILY_USD_CAP` in the Modal secret, default `3.00`, per API-NOTES §9.2's 6 × $3 line). The service refuses a job up front unless the day's spend plus its worst case fits: $2.24 for a 60 s clip, $1.12 for one of 30 s or less. So at $3 a day the judges share about one 60 s clip or two short clips a day; the landing page's demo never spends. To let several judges try it, raise it within the credits left (for example `10.00`: 6 days × $10 = $60 of the $150) before Nov 5, or keep $3 and tell judges in the form to use a clip of 30 s or less.
- [ ] **Decide when the judge codes open.** By default the judge, public and service windows open at 2026-11-05 00:00 UTC (`SAFECUT_CODE_WINDOWS`), after your planned submission (and 2 h before the official deadline, Nov 5 02:00 UTC); a judge who tries the app before then gets "this code isn't active yet" (the landing demo still plays). To open them at submission, set `SAFECUT_CODE_WINDOWS` in the Modal secret, e.g. `{"judge": ["2026-11-04T20:00:00Z", "2026-11-10T23:59:59Z"]}`, keeping the daily cap in mind.
- [ ] **The judge access codes** in `SAFECUT_ACCESS_CODES` (a JSON list in the Modal secret, never in the repo), for example `[{"code": "<12+ random characters>", "kind": "judge"}]` (judge and public codes share the daily cap; a `cap_usd` on them has no effect), plus the owner code (`"kind": "owner", "cap_usd": 6.0`) for the live smoke run (the owner code's `cap_usd` may not exceed $6: a higher value stops the API at startup). For the video recordings use a **recording** code instead (`"kind": "recording", "cap_usd": 15`, valid until Nov 3 23:59 UTC): at up to $2.24 reserved per 60 s clip, $15 covers the shot list with retakes. Type the judge code into the submission form's testing instructions only (paste the text of `docs/SUBMISSION.md`, then add the code in the form): never commit it, because the repo is public and anyone holding the code can spend the judges' daily cap.
- [ ] **The Vercel project and the domain**: import this repo in Vercel with root directory `web/`, add the domain `safecut.sigmora.org` (a CNAME to `cname.vercel-dns.com` at the DNS host), and set `NEXT_PUBLIC_SAFECUT_API` (the Modal API URL), `NEXT_PUBLIC_SAFECUT_HERO_ID` (`demo`, or `hero1` once recorded), `NEXT_PUBLIC_SIGMORA_URL`, `NEXT_PUBLIC_REPO_URL` and `NEXT_PUBLIC_PRIVACY_CONTACT` (the owner's privacy email for `/privacy`). Details in `web/README.md`.
- [ ] **`BASETEN_API_KEY`** (Baseten credits, for the Best Build on Meta Open-Weight Models bonus): add it to the cloud environment and the Modal secret, with `inference.baseten.co` allowed; then run probe h (`uv run python -m scripts.probes.probes h`, about $0.06) and set `SAFECUT_OPEN_WEIGHT_PRICE` and `SAFECUT_OPEN_WEIGHT_GRID_OK` from its summary. Then **turn the path on**, in both the cloud environment and the Modal secret: `SAFECUT_OPEN_WEIGHT_AUDIT=on` and `SAFECUT_OPEN_WEIGHT_CODE_KINDS=["owner", "recording"]` (it runs only on consented jobs from those codes; both default to off). Before `SAFECUT_OPEN_WEIGHT_CODE_KINDS` gets `owner` or `recording`, the hero cast signs the Baseten release addendum (PRE-A §3.8). Without these steps Muse Spark Open never runs, so don't claim it in the submission.
- [ ] **EgoBlur Gen 2 weights** (a gated download): open <https://www.projectaria.com/tools/egoblur/>, submit the request form with your own name and email, download `ego_blur_face_gen2.zip` and `ego_blur_lp_gen2.zip`, and unzip them to `ego_blur_face_gen2.jit` and `ego_blur_lp_gen2.jit` (never into this repo). (Optional, GPU machines only: point `SAFECUT_EGOBLUR_WEIGHTS_DIR` at the folder that holds them there; the deployed service has no GPU and keeps YuNet, so don't put them on its Volume.) **Run EgoBlur only where there is a GPU.** On a CPU it takes about 1.5 s per frame per detector (`docs/research/egoblur-gen2.md`): roughly 45 minutes for a 30 s clip. So **don't set `SAFECUT_DEPLOY_AUDIT` for the deployed service**: its container has 2 CPUs and no GPU, and every judge's render would audit for most of an hour. The deployed audit stays on the bundled YuNet (faces; plates by the red team), and says so in `audit.json` and the receipt. Use EgoBlur on a GPU machine only (`uv sync --group audit` there), and don't install the `audit` group on the machine that runs the test split unless it has a GPU (otherwise the `full` run audits for hours). To try it, check that `uv run python -c "from safecut.config import load_settings; from safecut.audit.detectors import load_detector; print(load_detector(load_settings()).model)"` prints `egoblur-gen2`. Until then the audit runs the bundled YuNet face detector (plates are left to the red team), and `audit.json`, the receipt and the README say so.

## Footage

- [ ] **Hero clips with signed releases** (`docs/SHOTLIST.md`): film them, upload to the private consented-clips bucket and give the cloud environment read access with `SAFECUT_CLIPS_URL` and `SAFECUT_CLIPS_TOKEN`. A session then records hero clip 1 with `scripts/go-live.sh` into `fixtures/jobs/hero1/` (consented clips only), labels it (`eval/labels/`), and the landing page switches to it with `NEXT_PUBLIC_SAFECUT_HERO_ID=hero1`. To make one the landing page's demo, record it with `bash scripts/go-live.sh fixtures/clips/<clip>.mp4 --id hero1 --consented` (consented: it has releases, and only a consented job can get the open-weight opinion), then set `"pinned": true` in its `fixtures/jobs/hero1/raw/manifest.json` (again after any `--replace` re-recording, which rewrites the manifest) (the API precomputes only pinned or demo recordings) and set the web's `NEXT_PUBLIC_SAFECUT_HERO_ID` to `hero1`.
- [ ] **The test split for the reported numbers**: on the owner's Mac (never in the cloud), `export MODEL_API_KEY=…` in that shell (a live run refuses to start without it, before it's counted), label the real-public clips per `docs/EVAL.md` §1, freeze them (`uv run python eval/run.py freeze --split test`) and **commit the frozen split before the first run** (a live run refuses an uncommitted tree). The split allows **3 runs in total, across all variants**, so run `--variant full` and `--variant blur_all` (the video's comparison needs both: `uv run python eval/run.py --split test --variant full`, then the same with `blur_all`), and keep the third for a re-run if one fails. A live run is all or nothing: it stops at `--max-usd` (default $15) or on a Meta error and keeps no partial result, so raise `--max-usd` to fit the split (about $3 per clip at most) before starting. The split file is `eval/splits/test.json` (`{"split": "test", "clips": [{"clip": "eval/private/<clip>.mp4", "labels": "eval/private/<clip>.json"}]}`, paths from the repo root); the clips and labels stay in the gitignored `eval/private/`, and **label each clip's prepared frames** (a run checks this first: a 60 fps phone clip is prepared at 30 fps). Commit `test.json` (paths only, no footage) with `test.sha256`, and commit `eval/splits/test.runs.json` with every run (it's how the 3-run limit holds beyond your machine). **After the runs**: `uv run python eval/report.py` (it rewrites `eval/RESULTS.md`, the README's table and the charts the video's CH-01 shows; CI's `eval/report.py --check` fails, and so blocks the deploy, until that output is committed), then fill `web/src/data/results.ts` (`RESULTS`, the landing page's table) from the same committed `metrics.json` files: `run_id` of the `full` run, one row per variant (`entity_recall` → `recall`, `exposure_rate` → `exposure`, `leak_bursts`, `over_blur`), `n_clips`, and the labelling facts only you have (`n_public`, `n_staged`, runs per clip, labellers and agreement), (the table has one run id: the `full` run's; the `blur_all` row's run id is in `eval/RESULTS.md`), then **rewrite the README's synthetic-only sentences** (the Status box, the line above the results table, and the "honest failures on this clip" paragraph) to describe the test split, and commit everything together; commit only the metrics they write (`eval/results/<run-id>/`).

- [ ] **The public split (SA-Co/VEval SmartGlasses, CC BY 4.0)**: accept the terms of `facebook/SACo-VEval` on Hugging Face with the owner's account, create a read token, and add it to the cloud environment as `HF_TOKEN` (with `huggingface.co` allowed). A session then downloads only the SmartGlasses split, writes `eval/splits/public.json`, and runs `eval/run.py --split public` once `MODEL_API_KEY` is set (tracking and leak-guard numbers only; it has no role labels).
